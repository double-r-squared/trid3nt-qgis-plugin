# ADR 0099 -- Mesh layer, wave M2 (GENERALIZE)

Status: accepted (2026-08-03)
Spec: docs/specs/mesh-layer-extraction.md (SIGNED, NATE 2026-08-03)
Follows: ADR 0098 (M1 EXTRACT). Scope: M2 = generalize drawn-geometry roles for
every engine, share the mesh preview/approve gate, add the MODFLOW DISV/gridgen
generator + per-region refinement, and complete the M1 carryover (re-point the
shim consumers, delete the shims, break the import cycle).

## Context

M1 extracted the mesh authoring layer and relocated the SWMM builder + the
mesh-preview constructors behind two compat shims. M2 generalizes the DOMAIN
stage: user-drawn structures now enter through ONE shared role vocabulary every
engine consumes, the preview/approve gate becomes a shared component, and the
refinement-capable groundwater grid (DISV) gets its generator.

## Decisions

### 1. Shared drawn-geometry roles (`agent/mesh/spatial_roles.py`)

The role parser that lived in `agent/gates/spatial_input.py` (roles {aoi,
barrier, point, line}) is generalized into a canonical 7-role vocabulary in the
mesh layer: **barrier | breakline | breach | refine_region | aoi_clip | boundary
| point** (+ neutral `line`). Legacy wire role `aoi` aliases to `aoi_clip`
(`ROLE_ALIASES`), so older clients round-trip unchanged. `parse_drawn_roles(fc)
-> DrawnRoles` is the single entry point; it preserves every error code + the
honesty floor of the M1 parser (a malformed FC never degrades to a silent
success). `gates/spatial_input.py` is now a thin backward-compat ADAPTER over it
(keeps `ParsedSpatialInput` + `parse_spatial_input_features` +
`barriers_feature_collection` + `split_features_by_role` +
`SpatialInputParseError` for the card/server/tests). The spatial-input tool
result (`gates/cards/spatial_input.py`) surfaces the new roles (`breach_point(s)`,
`refine_regions`, `breaklines`, `boundary_lines`) so the LLM can pass them to any
engine composer.

Per-engine consumption (how "every engine's workflow" reads a role):
- **SWMM barrier**: unchanged -- the drawn barrier FC snaps to cell-pair edges
  (relocated in M1 to `raster_cell_mesh._snap_barriers_to_edges`).
- **SFINCS / GeoClaw breach**: the composers already accept a `breach_point`
  `(lon,lat)` tuple (`sfincs/flood/flood.py:274`); the result now surfaces the
  DRAWN breach point as `breach_point` so a drawn value is PREFERRED when present
  (both accepted -- the tuple arg still works with no drawn point). The flow is
  LLM-mediated (composer arg), so no direct code binding was needed or added.
- **aoi_clip (SFINCS)**: characterized, NOT wired this wave (decision 4).
- **TELEMAC barrier**: characterized (decision 5).

### 2. Shared mesh preview/approve gate (`agent/mesh/preview_gate.py`)

NATE signed: tin paradigms default-ON (TELEMAC precedent), regular grids gate
only in USER-GATED mode. The component owns the ONE firing DECISION +
the gate envelope, and RIDES THE EXISTING pause/resume spine -- no new WS event,
no new confirmation envelope, **zero registry/contract growth**. It emits the
existing `PayloadWarningEnvelopePayload` carrying a `GranularitySuggestion`
(mesh stats), exactly the shape the TELEMAC mesh gate already emits, so
`server.py`'s `_PENDING_CONFIRMATIONS` block-and-wait + the
`tool-payload-confirmation` resume handle it unchanged; approve -> proceed,
`narrow_scope` + `revised_args[resolution_param]` -> re-mesh.

Mode-as-parameter: `mesh_gate_should_fire(paradigm, mode=None)`; `mode=None`
resolves to `default_gate_mode(paradigm)` = `user_gated` for tin, `auto` for
regular_grid/raster_cell_graph/amr_patches. This BAKES the signed
tin=ON/regular=OFF default while `mode` stays a real parameter.
**How the later input-gate wave plugs in**: it threads `mode="user_gated"` from
the run-mode lever into the regular-grid gate call sites -- no change to this
component. The gate envelope's `engine`/`resolution_param` are the EXISTING
closed Literals (`swmm|sfincs|dem|topobathy|landcover|telemac` /
`target_resolution_m|grid_resolution_m|resolution_m|mesh_resolution_m`), so no
contract enum grew. MODFLOW is not in the enum; its DISV gate (when it lands
live) is the one justified future enum addition.

RESIDUAL (characterized follow-on): the live TELEMAC gate still runs through the
existing `_build_telemac_mesh_envelope`. Folding it onto
`build_mesh_gate_envelope` is deferred to avoid destabilizing the live river_dye
path without a full live drive; the shared component is unit-proven to emit the
identical envelope shape.

### 3. MODFLOW DISV / gridgen generator -- BUILT, live leg STOPPED

Added IN `gwt_adapter.py` (not a sibling -- the dual flat/package import
constraint of ADR 0098 decision 3): `gridgen_available()`, a typed
`GridgenUnavailableError` (error_code `MODFLOW_GRIDGEN_UNAVAILABLE`),
`_disv_refinement_features` (pure lon/lat -> local-grid reprojection + quadtree
level from `target_size_m`), `_build_disv_gridprops` (StructuredGrid -> gridgen
refine -> `get_gridprops_disv`), and `_build_gwf_disv` (the DISV analogue of
`_build_gwf_dis`). The capture_zone / wellhead_protection PRT archetype gains an
opt-in `refine_regions` param threaded through `build_modflow_deck`; **default
None => the uniform DIS grid is byte-identical** (162->140 passed + 13 mf6-skip,
capture_zone default still writes `.dis`, no `.disv`).

**IMAGE FINDING + STOP condition**: `flopy Gridgen` shells out to the USGS
`gridgen` binary at `build()`; that binary is NOT on PATH and NOT in the modflow
worker image (`services/workers/modflow/Dockerfile` installs only mf6 + flopy
via pip; `which gridgen` = absent, `gridgen_available()` = False). Per the
signed spec the component is built + tested offline and the LIVE DISV leg STOPS
honestly: a drawn `refine_region` on capture_zone raises
`GridgenUnavailableError` (naming the Dockerfile image-rebuild condition) BEFORE
any partial deck is written -- never a silent degrade to DIS.

NAMED CONDITIONS to unblock the live DISV leg:
1. Add the USGS `gridgen` binary to `services/workers/modflow/Dockerfile`
   (container-image-hygiene: gridgen is a ~2-4 MB statically-linked binary from
   the USGS `modflow6`/`gridgen` release; a single `curl + unzip` layer with a
   SHA-256 pin, mirroring the mf6 install -- negligible image-size impact,
   report the exact delta at rebuild time).
2. Port the downstream capture_zone WEL/CHD/PRT packages from structured
   `(lay,row,col)` cellids to DISV `(lay,node)` vertex cellids (the release
   points, the CHD boundary, the WEL cell). The M2 seam STOPs before this code
   so no half-built vertex deck is emitted; this port is the named follow-on the
   STOP gates (M3-adjacent).

### 4. aoi_clip (SFINCS) -- CHARACTERIZED, not wired (no flood-seam touch)

Where the mask enters (verified): the SFINCS domain clip is WORKER-side, in
`services/workers/_sfincs_build/deck.py` `_generate_hydromt_yaml_config` at the
`setup_mask_active` block (~:1901-1935). It is NOT worker-side-BLOCKED -- the
building-obstacle path already burns a vector polygon into the mask as
`exclude_mask` (msk=0 inactive), so an `aoi_clip` polygon plugs in as an
`include_mask` (keep only AOI cells active) on `setup_mask_active`, staged
locally, carried through `services/workers/_sfincs_build/spec.py` options. The
server side (`agent/mesh/spatial_roles.py`) already parses the `aoi_clip`
polygon + bbox and surfaces it.

DECISION: wire the server-side parse/surface (done) but DEFER the worker-side
`include_mask` insertion. Rationale: the worker deck change touches the SFINCS
flood-solve seam (flood canary MANDATORY) and needs a hydromt worker build +
live drive to prove; landing it blind would violate the canary discipline. Per
the signed spec this is the honest characterization path (the clip is doable
worker-side, the exact seam is named, and NO post-solve fake-clip substitute was
used). Because no flood-seam file was touched this wave, the flood canary is NOT
mandated by M2. CONDITION to wire: a scoped SFINCS-worker job adds the
`include_mask` + `spec.py` option under a flood canary.

### 5. TELEMAC barrier -- CHARACTERIZED (M4-adjacent)

A drawn `barrier` in a TELEMAC channel mesh means a wall/obstruction in the
triangulated domain: either a HOLE (an internal no-flow island, like the
existing island-hole carving in the gmsh mesher) or a BREAKLINE the
triangulation forces edges along. Both are gmsh operations 100% worker-side
(GPL-isolated, `telemac_river_dye_build.py`). The `breakline` role now carries
the geometry to the worker; applying it as a gmsh constraint is worker-side mesh
work adjacent to M4 (the quadtree/tin build). Honest characterization is the
accepted M2 deliverable for TELEMAC per the spec.

### 6. refine_regions component (`agent/mesh/refine_regions.py`)

Server-side, pure: `mesh_sizing_from_refine_regions(refine_regions, base_size_m)
-> MeshSizingSpec` (per-region `target_size_m` + quadtree `refine_level` via
`ceil(log2(base/target))`). It computes the sizing SPEC server-side; the worker
applies it. Consumed by the DISV proof (worker duplicates the tiny level math
behind the Docker COPY boundary -- fold-by-duplication) and characterized for
TELEMAC gmsh sizing fields (data-only pass-through when the worker seam allows).

### 7. M1 carryover complete

- Re-pointed all shim consumers (server.py, solver_confirm, run_swmm,
  postprocess_swmm, model_urban_flood_swmm + 6 test files) from
  `workflows.swmm.swmm_mesh_builder` -> `agent.mesh.raster_cell_mesh` and
  `workflows.shared.mesh_layer` -> `agent.mesh.mesh_preview`.
- DELETED both compat shims (DELETION_LEDGER rows CONDITION-MET -> DELETED).
- Broke the `agent/mesh` <-> `agent/workflows/swmm` import cycle: the
  `swmm_hyetograph` import in `raster_cell_mesh` is now lazy (inside
  `build_swmm_mesh`), and the dead `load_manning_mapping` re-export (the actual
  cycle trigger -- it forced the heavy `workflows` package __init__) is removed
  (real consumers import it from `workflows.shared.manning` directly). Direct
  `import raster_cell_mesh` now works standalone; consumer tests 82 passed.

## Consequences

- New mesh components: `spatial_roles.py`, `refine_regions.py`,
  `preview_gate.py` (server) + DISV helpers in `gwt_adapter.py` (worker).
  Registry / coded-tool / spec-served counts UNCHANGED (175) -- refactor +
  components, not a tool landing. No new WS event, no new contract enum.
- Two shims deleted; the import cycle 0098 flagged is resolved.
- Offline baseline unchanged (the documented 9 failures).
- Flood canary NOT mandated (no flood-seam file touched -- aoi_clip characterized
  worker-side, not wired).
