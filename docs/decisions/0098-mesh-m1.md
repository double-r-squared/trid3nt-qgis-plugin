# ADR 0098 -- Mesh layer, wave M1 (EXTRACT)

Status: accepted (2026-08-03)
Spec: docs/specs/mesh-layer-extraction.md (SIGNED, NATE 2026-08-03)
Follows: the mesh census (agent aacb31e). Scope: M1 = extract the mesh authoring
layer + relocate the SWMM builder and generalize the preview, ZERO behavior
change (byte/value-identical decks on golden fixtures = the gate).

## Context

Data has its universal ingest layer; compute has workers + templates; MESH was
the last model pillar still scattered as private steps inside engine composers.
M1 extracts it into `server/src/trid3nt_server/agent/mesh/` and folds the
concrete duplications the census named -- fold by DUPLICATION, not abstraction
(the mesh landscape stays heterogeneous; the layer chases reusability).

## The load-bearing finding: the server/worker split is a hard boundary

Every worker Docker image COPYs ONLY `services/workers/*` -- never `server/`
(verified: sfincs/swan/modflow/telemac Dockerfiles). So the three engine deck
AUTHORS that emit a regular grid physically cannot import a server-side mesh
component:

- SFINCS regular-grid cell math is WORKER-side (hydromt `setup_grid_from_region`
  in `_sfincs_build/deck.py`); the server composes RESOLUTION only
  (`suggest_sfincs_resolution_from_bbox`).
- SWAN `_grid_geometry` (`swan/deck_builder.py`) is a pure worker-side string
  render (spans in DEGREES) -- the deck author's own contract.
- MODFLOW DIS delr/delc is WORKER-side (`modflow/gwt_adapter.py`, imported FLAT
  as `gwt_adapter` server-side and as a package worker-side).
- TELEMAC gmsh + the triangle-wireframe preview are 100% worker-side (GPL
  isolation is load-bearing).

So the spec's "grid_geometry, three consumers" premise resolves the honest way
the spec authorized ("document the split honestly"): the SERVER `grid_geometry`
component owns the canonical regular-grid math for the SERVER surface (the NEW
preview), and each worker keeps its paradigm-native derivation behind the
build-isolation boundary. Worker-side folds land in the worker tree.

## Decisions

### 1. The mesh package (`agent/mesh/`)

- `grid_geometry.py` (NEW) -- `regular_grid_from_bbox(bbox, resolution_m)` ->
  `RegularGrid` (origin / spans / cell size / row-col counts). Pure stdlib math;
  deg<->m via the SFINCS/SWMM autoscaler convention (111_320 m/deg lat, *cos lon).
- `raster_cell_mesh.py` -- the SWMM DEM-cell builder RELOCATED verbatim from
  `workflows/swmm/swmm_mesh_builder.py` (git mv, history preserved). The public
  function surface is identical.
- `mesh_preview.py` -- the mesh-preview constructors RELOCATED from
  `workflows/shared/mesh_layer.py` (git mv) + GENERALIZED: a NEW
  `regular_grid_outline_feature_collection` / `make_grid_outline_layer_uri` give
  the regular-grid paradigm (SFINCS/SWAN/MODFLOW) their FIRST visible mesh
  (extent + cell-size annotation + decimated gridlines), and the module now
  documents all four paradigms it styles (SWMM cells, SFINCS quadtree, TELEMAC
  wireframe, regular-grid outline) under one `style_preset="mesh_grid"` contract.

### 2. Compatibility shims (M2 removes them)

The two relocated files leave a thin re-export shim at their OLD path
(`workflows/swmm/swmm_mesh_builder.py`, `workflows/shared/mesh_layer.py`) that
mirrors the FULL module namespace (public + private helpers) so the current
consumers (run_swmm / postprocess / solver / model composers / tests) keep
resolving unchanged -- including tests that reach private helpers
(`_read_and_resample_dem`, `_active_cells_from_deck`) via the old module path.
This is the identity-safe "move + re-export" the spec sanctions; the shims are
DELETION_LEDGER rows whose CONDITION is the M2 consumer re-point.

### 3. `dis_grid` folds IN the modflow worker (in-file)

The 5 `flopy.mf6.ModflowGwfdis` call sites in `gwt_adapter.py` (serving 12
archetype decks) fold into ONE `_build_gwf_dis(...)` constructor helper. Home =
in `gwt_adapter.py` itself, NOT a sibling module: gwt_adapter is imported FLAT
(`import gwt_adapter`, dir on sys.path) server-side and as a PACKAGE
(`services.workers.modflow.gwt_adapter`) worker-side, so neither a relative nor a
flat sibling import resolves in both contexts. The helper omits xorigin/yorigin
when absent (the local-(0,0)-origin decks) and tags the model grid only when an
origin + crs are given -- the written `.dis` is byte-identical to each original
call. Gate: the modflow worker deck tests pass (162 passed) + server template
tests green.

### 4. TELEMAC channel_tin: preview generalization only

The TELEMAC mesher is 100% worker-side already (gmsh triangulation + the
wireframe geojson generator both in the GPL-isolated worker; the server side is
pure orchestration -- `_build_telemac_mesh_envelope` calls `preview_telemac_mesh`
and publishes the worker's `mesh_preview.geojson`). There is NO server-side
duplication to extract. The M1 deliverable for TELEMAC is therefore the
`mesh_preview` generalization: the component documents the TELEMAC triangle
wireframe as a first-class consumer that it styles/publishes verbatim.

### 5. RIDER -- CaMa forcing sampler EXCISED (NATE-approved)

The orphaned `discharge_forcing_from_cama_cog` sampler + `cama_cog` /
`cama_cog_uri` plumbing (adapter fn + `__all__` + `build_surge_forcing` param +
branch, autowire import + branch, flood.py comment, docstrings) are DELETED --
no registered tool has produced a CaMa COG since `fetch_cama_flood_discharge`'s
deletion (ADR 0095). Resolves the ADR 0095 QUEUED ledger row. No test coupled to
the sampler (`build_surge_forcing` tests pass unchanged). Flood-seam touch ->
flood canary mandated.
