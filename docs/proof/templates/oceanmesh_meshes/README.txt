OceanMesh2D standalone coastal meshes (ADR 0192 sandbox)
=========================================================

These are shoreline-following, gradation-limited triangular meshes generated by
the authentic CHLNDDEV oceanmesh (OceanMesh2D Python port) for four US coastal
AOIs. Each was built from real shoreline + real NOAA/USGS topobathy (ETOPO 2022
base + CUDEM 1/9" + 3DEP). Feature_sizing (distance-to-shore) and wavelength_sizing
(shallow-water wavelength from bathymetry) are active, gradation-limited (g=0.2).

Shoreline source per AOI:
  * delaware_bay, tampa_bay -- HIGH-RES WATER EDGE (ADR 0194): OSM natural=coastline
    + connected NHDPlus HR areal water, meshed full-bay with a custom SDF (the v1
    GSHHG-intermediate versions were "close but not really" aligned; see below).
  * duck_nc, puget_sound    -- v1 GSHHG intermediate L1 (ADR 0192), land faces deleted.

Files per AOI (<aoi> = delaware_bay | duck_nc | tampa_bay | puget_sound):
  <aoi>.2dm          SMS 2dm mesh, node Z = topobathy elevation (positive-up).
                     MDAL-native -- opens directly in QGIS.
  <aoi>.slf          SELAFIN / SERAFIN geometry (TELEMAC-2D), single variable
                     BOTTOM = elevation. MDAL-readable AND TELEMAC-loadable.
  <aoi>_hgrid.gr3    SCHISM hgrid.gr3, node depth positive-down.
  <aoi>.fort.14      ADCIRC/SWAN(unstructured) grid, depth positive-down (bonus).

Load in QGIS (either file type):
  Layer > Add Layer > Add Mesh Layer... > select <aoi>.2dm  (or <aoi>.slf)
  The mesh renders immediately; the dataset group (Z / BOTTOM) carries the
  bathymetry -- style it via the layer's Symbology > Contours/Datasets.

TELEMAC use: <aoi>.slf IS a valid TELEMAC-2D geometry file (proved by reading it
back with the openTELEMAC data_manip SERAFIN reader). Point a TELEMAC steering
file GEOMETRY FILE at it, or open in BlueKenue.

All coordinates are EPSG:4326 (lon/lat degrees).
Regenerate: scripts/sandbox/oceanmesh/build_coastal_mesh.py (duck_nc, puget_sound)
            scripts/sandbox/oceanmesh/build_coastal_water_edge_mesh.py (delaware_bay, tampa_bay)

-----------------------------------------------------------------------------
ADR 0194 -- HIGH-RES COASTAL WATER-EDGE re-mesh (build_coastal_water_edge_mesh.py)
-----------------------------------------------------------------------------
NATE flagged the v1 GSHHG-intermediate estuary meshes as not aligned with the
real water edge. delaware_bay and tampa_bay are re-meshed against a high-res
WATER polygon (water_edge.py):
  * OSM natural=coastline ways via Overpass (3-mirror etiquette, the repo's
    reliable OSM path) polygonized + classified into a water polygon (water lies
    to the RIGHT of a coastline way), islands preserved as holes;
  * UNIONed with connected NHDPlus HR NHDArea (SeaOcean / StreamRiver-area) +
    NHDWaterbody polygons, adding river arms the coastline generalizes over,
    clipped to the domain.
NOAA CUSP was evaluated as the production-grade source but has NO public
queryable ArcGIS vector layer (download-only via the Shoreline Data Explorer),
so OSM coastline is the landed high-res source (verdict in the proposal doc).

The domain is the WHOLE bay (natural closure: land inland, a straight offshore
open boundary seaward) -- NOT the tight v1 AOI box, which is drawn only as a
residual overlay and does not truncate the mesh. Meshing uses a custom SDF over
the exact water polygon (_mesh_water_edge_incontainer.py, mounted not baked): the
coastal om.Shoreline path is bypassed because it models polygons exterior-ring-
only (drops island holes) and Chaikin-SMOOTHS the shoreline, both of which move
the meshed edge OFF the imagery.

Meshes (same 4-format emission, MDAL + SERAFIN verified):
  delaware_bay  full bay -75.60..-74.82 x 38.72..39.55; 5308 nodes / 9422 elems;
                107-4292 m (median 420 m); min qE 0.52 median 0.95; 0 inverted;
                closed (6 loops). water 3953 km^2.
  tampa_bay     full bay -82.90..-82.38 x 27.48..28.06; 10797 nodes / 18726 elems;
                84-3043 m (median 273 m); min qE 0.43 median 0.96; 0 inverted;
                closed (18 loops). water 2262 km^2 (incl. NHD river arms).
Proof renders: docs/proof/templates/oceanmesh_standalone_{delaware_bay,tampa_bay}.png
+ _closeup companions (mesh edge vs ESRI imagery: barrier islands / river arms).

-----------------------------------------------------------------------------
ADR 0193 -- WATERSHED-FIRST river meshes (scripts/sandbox/oceanmesh/build_watershed_mesh.py)
-----------------------------------------------------------------------------
NATE's watershed-then-mesh method: the mesh DOMAIN is a delineated watershed
(pysheds catchment), NOT a bbox -- the AOI box never truncates the mesh. The
element size is refined by DISTANCE TO the NHDPlus HR / OSM river network within
the catchment (fine along the valleys, coarse on the ridges). The catchment
interior is meshed by a custom signed-distance function handed to OceanMesh2D's
generate_mesh (the coastal Shoreline path only meshes water touching the region
boundary and cannot mesh a fully-enclosed inland catchment).

Cases (<case>):
  coweeta_river   Coweeta Creek watershed, Nantahala Mtns NC. 3DEP 10 m DEM
                  (EPSG:5070 -> 4326). Catchment 30.0 km^2; mesh 4956 nodes /
                  9727 elements; resolution 31-272 m (median 69 m); min qE 0.72
                  median 0.97; 0 inverted; single closed boundary. MDAL- and
                  SERAFIN-verified. Same 4-format emission as the coastal cases.
