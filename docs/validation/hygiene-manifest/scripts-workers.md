# Hygiene manifest - `scripts/` + `workers/`

Read-only lens. Every tracked file in the scope was opened end to end by the
agent that wrote its row; the greps at the bottom are sweep guards run AFTER the
read, never the census. `__pycache__/`, `workers/.pytest_cache/` and the four
untracked `scripts/sandbox/oceanmesh/shoreline/GSHHS_i_L1.*` shapefile parts are
untracked and out of scope.

Pure LOC is `scripts/loc_report.py`'s measure with the same correction the other
manifests carry: the instrument subtracts blank lines and docstring lines
independently, so a blank line INSIDE a docstring is subtracted twice. The `pure
LOC` column is the corrected count; the parenthesised figure is what
`loc_report` prints today. Over this scope the defect understates pure code by
299 lines (12,208 corrected against 11,909 reported), and it drives
`workers/telemac/__init__.py`'s negative (`-1`). `.sh`, `Dockerfile` and
`.dockerignore` rows use total minus blank minus full-line-comment, which has no
docstring term and needs no correction.

NO file in this scope carries an LLM-facing docstring: there is no
`@register_tool` and no `__doc__` assignment anywhere under `scripts/` or
`workers/` (the three `register_tool` hits are `code_graph.py` naming the
decorator as a whitelist rule), so the 1,000-char front budget governs nothing
here. Every docstring is an internal one under the 3-line (function/class) /
5-line (module) limit.

FATES cite `docs/validation/scripts-eval.md` where the SCRIPTS RULED entry
settled them (five-directory structure, six DELETE, nine ATTIC, six to
`scripts/local/`, the two mesh-format modules out of `scripts/` entirely). Where
this read found something the eval did not, the `notes` column says so and the
fate is unchanged - the wave never relitigates a ruling.
