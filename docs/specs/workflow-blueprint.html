2. Workflow shape

A workflow is a fixed spine of steps; templates supply values, never structure. Each step that touches an engine delegates to that engine's official library — we write the thin agnostic call, the library does the domain work. SELECT and COLLECT are fully agnostic. SOLVE and EMIT are today's machinery, untouched. The only new construction is MESH.

flowchart TD
    SELECT["SELECT — retrieval, template roster"]
    COLLECT["COLLECT — doors + fetcher substrate → resolved sheet (as today)"]
    MESH["MESH — MESH declaration → session + edits → MeshArtifact"]
    AUTHOR["AUTHOR — sheet → engine deck (deck/manifest = sole authored record)"]
    SOLVE["SOLVE — box dispatch, --network none (as today)"]
    EMIT["EMIT — one seam, styles.yaml (frozen)"]
    SELECT --> COLLECT --> MESH --> AUTHOR --> SOLVE --> EMIT
    MESH -. delegates .-> M2["meshers: OceanMesh2D, telapy mesh.py, HEC-RAS mesher, regular grid"]
    AUTHOR -. delegates .-> A2["official libs: TelemacCas + .slf, flopy, SWMM .inp, HEC-RAS project"]
    SOLVE -. delegates .-> S2["existing workers, one per engine: staged run dir in, results out"]
    EMIT -. delegates .-> E2["readers: TelemacFile (SELAFIN), heads, out.rpt, plan HDF"]

3. Input vocabulary (descriptive, not a change)

Nothing about how inputs are formatted, resolved, or stored changes: the resolved sheet, the doors, the journal, and rerun stay exactly as they are. The five categories are words for talking about inputs — what any simulation's input set looks like — useful in forms, docs, and gate conversation. Not a schema; nothing gets re-categorized.

categorymeaning
geometrymesh or domain — where the simulation lives
boundary conditionsthe world pushing on the run: inflow, tide, rain, wind
initial conditionsthe state at t=0: initial water level, thermocline
physical parametersmaterial truth: friction, dispersion, decay rates
numerical parametersdiscretization: spatial resolution, time step, duration

4. The mesh tool (the new construction)

Fetch = declarative specs + one router; styles = declarative presets + one seam; mesh = a parametric spec + a registry of named edit actions wrapping official mesher libraries. The policy classes (MeshPolicy, CorridorPolicy, CatchmentPolicy) die into spec fields; MeshArtifact stays as the convergence point. One OceanMesh2D build feeds TELEMAC, SWAN and SCHISM alike — which is why the mesh tool stands alone.

4.1 Signature — a declaration block, like DATA and PARAMS

# module level in the template, beside DATA and PARAMS — frozen, NOTHING builds at import
MESH = tool.build_mesh(
    mesher = "om2d",              # om2d | telapy_mesh | hecras | reg_grid
    kind   = "unstructured_tri",  # structured_grid | unstructured_tri |
                                  #   unstructured_quad_flex | curvilinear | node_link
    aoi    = P.aoi,               # or the workflow's domain
    refine = {"edge_length": P.edge_length, "min_spacing": 25, "gradation": 0.15},
    bed    = D.dem,               # bathymetry via the frozen fetch subsystem
).edit("add_obstacle", D.breakwaters)   # a DECLARED edit: the recipe's prefix

# the SAME tool called standalone (agent / user / driver) builds now and
# stashes the MeshArtifact in the case for discovery:
tool.build_mesh(mesher="om2d", kind="unstructured_tri", aoi=aoi, ...)

# at runtime, when the plan first demands MESH, a SESSION opens over the
# declaration; gate-time edits APPEND to the declared chain:
session.edit("set_boundary",  side="seaward", type="open")
session.edit("refine_region", geometry=harbor_poly, edge_length=10)
session.edit("restart")       # truncates back to the declared prefix
session.accept()              # -> MeshArtifact (.slf / .gr3 / fort.14 + MDAL display)

4.2 Edit-action registry — where all three surfaces converge

Each mesher registers named actions with typed inputs: thin hooks wrapping the library's own functions, never reimplementations. The router validates a spec and an edit against the registering mesher's declared fields, loudly — the bag is typed at the router, not by Python classes. An action never cares who authored its inputs:

  • direct — code and drivers call actions with params;
  • agent — generated tools, one per registered action, mounted only while a MeshSession is open, unmounted on accept;
  • user-drawn (later) — QGIS drawings deliver geometry into the same actions.

4.3 Gate loop

flowchart LR
    B["default build (demand-pulled)"] --> G["GATE presents: MDAL layer + probes"]
    G -- "user speaks" --> E["agent calls edit(...) — scoped tools only"]
    E --> R["rebuild: probes + snapshot"]
    R --> G
    G -- "QGIS hand-edit" --> Q["edit('apply_layer_edits', layer)"] --> R
    G -- accept --> A["MeshArtifact"]
    G -- restart --> T["chain truncated to declared prefix"] --> G

USER-GATED mode runs this loop; AUTO mode builds inline and skips it. Boundary definition lives in the same loop. After a hand-edit the compat gate re-checks and solver-format translation runs as normal.

4.4 The recipe is the record

A mesh IS (spec + ordered edit chain), journaled — deterministic rebuild by replay; restart truncates; rerun and provenance come free. A QGIS hand-edit enters as one recorded action carrying the edited layer's hash: honestly non-replayable, while everything around it still is.

mesh_recipe.jsonl
  {"spec": {"mesher": "om2d", "kind": "unstructured_tri", "refine": {...}}}
  {"edit": "add_obstacle",      "geometry": "sha256:...", "source": "fetch_osm_breakwaters"}
  {"edit": "set_boundary",      "side": "seaward", "type": "open"}
  {"edit": "apply_layer_edits", "layer": "sha256:...", "replayable": false}

4.5 Agent eyes

Every action returns numeric probes — node/element count, edge-length histogram, min-angle quality, boundary segments, obstacle count — and the session renders a wireframe snapshot the agent reads with vision. The human at the gate stays the final eye.

4.6 Supplied mesh + laziness

  • Explicit-first, discovery-second: an explicit mesh argument on the run always wins; else the router discovers compatible MeshArtifacts already authored in the case and offers them at the gate; else the declared spec builds the default.
  • Demand-pull: the build fires when a downstream step first demands the artifact — the form stays cheap, refused runs cost nothing.

5. QGIS translation placement

Split by audience. mesh/ owns solver formats (.slf, .gr3, the HEC-RAS bundle): solver food. emission owns the display face (domain mesh → MDAL-loadable layer): a mesh is just another data type on the one emission seam, like rasters, vectors, and series. The .2dm writer moves out of generate_mesh onto the seam when the mesh wave lands.

Razor: feeds a solver → mesh/'s business; feeds a screen → emission's. One seam per audience, no third place.

5.1 Emission stays declarative (frozen subsystem)

Products declare a quantity; styles.yaml resolves the look; .style() overrides declaratively; restyle_layer changes the display face only. The seam generalizes by data type, never by engine:

6. Class view

The classes the mesh wave builds. Downstream of MeshArtifact, everything is today's machinery: the deck writers, the box dispatch, the emission seam. Stepping via telapy is out of spec — the existing run paradigm carries everything; stepping arrives later for free.
