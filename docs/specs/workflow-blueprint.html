1. Where the architecture stands

A workflow is a fixed spine of steps; templates supply values, never structure. Each step that touches an engine delegates to that engine's official library. Terminology: an engine is a solver (TELEMAC, MODFLOW, SWMM, HEC-RAS); a mesher is a mesh-building library; a fetcher is a data spec; the box is the network-isolated container an engine runs in.

2. What is being added: the mesh tool

One tool family shaped like fetch: a parametric spec + a registry of named edit actions wrapping official mesher libraries. MeshArtifact stays as the convergence point. One OceanMesh2D build feeds TELEMAC, SWAN and SCHISM alike, which is why the tool stands alone from any engine.

2.1 Signature — a declaration block, like DATA and PARAMS

# module level in the template, beside DATA and PARAMS — frozen, NOTHING builds at import
MESH = tool.build_mesh(
    mesher = "om2d",              # om2d | telapy_mesh | hecras | reg_grid
    kind   = "unstructured_tri",  # structured_grid | unstructured_tri |
                                  #   unstructured_quad_flex | curvilinear | node_link
    aoi    = P.aoi,               # or the workflow's domain
    refine = {"edge_length": P.edge_length, "min_spacing": 25, "gradation": 0.15},
    bed    = D.dem,               # bathymetry via the frozen fetch subsystem
).edit("add_obstacle", D.breakwaters)   # a DECLARED edit: the recipe's prefix

# the SAME tool called standalone (agent / user / driver) builds now and
# stashes the MeshArtifact in the case for discovery:
tool.build_mesh(mesher="om2d", kind="unstructured_tri", aoi=aoi)

# at runtime, when the plan first demands MESH, a SESSION opens over the
# declaration; gate-time edits APPEND to the declared chain:
session.edit("set_boundary",  side="seaward", type="open")
session.edit("refine_region", geometry=harbor_poly, edge_length=10)
session.edit("restart")       # truncates back to the declared prefix
session.accept()              # -> MeshArtifact (.slf / .gr3 / fort.14 + MDAL display)

2.2 Edit-action registry

Each mesher registers named actions with typed inputs: thin hooks wrapping the library's own functions, never reimplementations. The router validates a spec and an edit against the registering mesher's declared fields, loudly. An action never cares who authored its inputs, so all three invocation surfaces converge on it:

  • direct — code and drivers call actions with params;
  • agent — generated tools, one per registered action, mounted only while a MeshSession is open, unmounted on accept;
  • user-drawn (later) — QGIS drawings deliver geometry into the same actions.

2.3 Gate loop

flowchart LR
    B["default build (demand-pulled)"] --> G["GATE presents: MDAL layer + probes"]
    G -- "user speaks" --> E["agent calls edit(...) — scoped tools only"]
    E --> R["rebuild: probes + snapshot"]
    R --> G
    G -- "QGIS hand-edit" --> Q["edit('apply_layer_edits', layer)"] --> R
    G -- accept --> A["MeshArtifact"]
    G -- restart --> T["chain truncated to declared prefix"] --> G

USER-GATED mode runs this loop; AUTO mode builds inline and skips it. Boundary definition lives in the same loop. After a hand-edit the compat gate re-checks and solver-format translation runs as normal. Every action returns numeric probes (node/element count, edge-length histogram, min-angle quality, boundary segments, obstacle count) and a wireframe snapshot the agent reads with vision; the human at the gate stays the final eye.

2.4 The recipe is the record

A mesh IS (spec + ordered edit chain), journaled — deterministic rebuild by replay; restart truncates; rerun and provenance come free. A QGIS hand-edit enters as one recorded action carrying the edited layer's hash: honestly non-replayable, while everything around it still is.

mesh_recipe.jsonl
  {"spec": {"mesher": "om2d", "kind": "unstructured_tri", "refine": {...}}}
  {"edit": "add_obstacle",      "geometry": "sha256:...", "source": "fetch_osm_breakwaters"}
  {"edit": "set_boundary",      "side": "seaward", "type": "open"}
  {"edit": "apply_layer_edits", "layer": "sha256:...", "replayable": false}

2.5 Mesh resolution order + laziness

  • Explicit-first, discovery-second: an explicit mesh argument on the run always wins; else the router discovers compatible MeshArtifacts already authored in the case and offers them at the gate; else the declared spec builds the default.
  • Demand-pull: the build fires when a downstream step first demands the artifact — the form stays cheap, refused runs cost nothing.

        reg_grid.py       # regular grid

Each mesher file registers its own edit actions beside its build — adding a mesher is one file, exactly as adding a fetcher is one spec. What empties out: workflows/mesh/generate_mesh/ dissolves (its builders become registered meshers; its standalone-tool role IS tool.build_mesh called standalone); lib/slots.py sheds MeshPolicy; telemac/workflow.py sheds CorridorPolicy and MeshHandle. The existing templates are the migration targets — each one's mesh declaration is rewritten as in section 5.

5. Worked example: telemac_river_dye

The delta on the real template (workflows/telemac/river_dye/river_dye.py, 261 lines): only the two mesh policy blocks, one line of plan, and the custom approve-mesh gate metadata change. DATA, PHYSICS, FORCING, ANSWER, the chart, coercions, sensitivity and provenance are untouched.

5.1 Before (today, river_dye.py:110-135)

MESH = MeshPolicy(resolution=P.mesh_resolution, target_edge_m=P.mesh_resolution_m)

CORRIDOR = CorridorPolicy(extent_km=P.reach_length_km,
                          width_m=P.channel_width_m,
                          boundary_source=P.bank_source)

def plan(ops):
    return [
        FormGate(title="Review the river-tracer scenario"),
        DrawGate(param="release_coords", geometry="point", ...),
        *ops.acquire_domain(location=P.location, bbox=P.bbox, rivers=D.rivers, ...),
        ops.author(mesh=ops.build_mesh(Ref("reach"), MESH, corridor=CORRIDOR),
                   physics=PHYSICS, forcing=FORCING),
        ops.solver_spec(compute_class=P.compute_class, physics=PHYSICS),
        ops.read_results(Ref("solve"), ...).chart("dye_concentration", ...),
    ]

5.3 What each change buys

  • ops.solver_spec renames to ops.solve — the plan names what the step is, not how it is implemented; pure rename, riding this same wave.
  • Two policy classes collapse into one declaration block. The corridor shape fields do not die — they become spec fields the registered corridor_tin mesher declares and the router validates loudly. (corridor_tin is today's reach mesher lifted out of the deck writer; a candidate for later replacement by om2d, not pretended done.)
  • The custom approve-mesh gate is deleted. The template-specific GateSpec(kind="solver", estimate_provider=..., pin_provider=...) metadata (~15 lines) is subsumed by the standard mesh gate loop — an upgrade: today the user can only preview and pin resolution; now every registered edit action is available at that gate ("refine near the release point", hand-edit the MDAL layer).
  • A supplied mesh works here for free (explicit argument or case discovery), which today's template cannot accept.
  • ResolutionSpec and everything else stays — the 3 m floor declaration, sensitivity labels, provenance rows, coercions: untouched.
