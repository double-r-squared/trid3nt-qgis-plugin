0. How meshing works (primer)

An unstructured mesh is a domain cut into triangles. Two things define its quality: the SHAPE of the triangles (minimum angle - skinny slivers break solvers) and the SIZING - a field h(x) giving the target edge length at every point. Everything a mesher does is in service of honoring h(x) with well-shaped triangles.

0.1 Sizing functions - oceanmesh's actual specialty

Coastal sizing is domain knowledge: distance-to-shore (fine at the coast, coarse offshore), wavelength (enough elements per tidal wavelength, which depends on depth), bathymetric gradient (fine where the bed is steep), and a gradation cap (neighboring sizes may differ by at most g percent, so fine regions blend smoothly into coarse ones). This composed h(x) grid is what om2d computes better than any general-purpose tool - it is why om2d stays in every wiring.

0.3 Conformality, and why edits usually mean regeneration

A breakline or obstacle outline is CONFORMAL when its vertices ARE mesh nodes and its segments ARE element edges - zero offset. The natural way to get that is to feed the constraint INTO generation (om2d pfix, gmsh embedding): the mesher builds around it. Retrofitting a constraint into a finished mesh is hard - there is no node where you need one, and moving/inserting nodes ripples into neighboring triangle quality. That is the structural reason the community default for "edit a mesh" is "change the inputs and regenerate", and why the surgical alternatives measured badly here (80.1 m offset).

0.4 Cost scaling - why regeneration is fine in the common case

Node count scales like area / h^2. A screening-resolution coastal AOI is hundreds to tens of thousands of nodes - seconds to regenerate (measured: 285-node spot-check mesh in 3.5 s end-to-end; the Duck NC om2d build well under a minute in-container). Regeneration only starts to hurt at large fine meshes (hundreds of thousands of nodes, minutes per build) - which is the flagship/production end, not the common case.

0.5 Boundaries and formats

After generation, the exterior loop gets classified: OPEN stretches (where tide/surge forcing enters - must be contiguous runs of nodes) vs LAND. Solvers are strict bookkeepers about this: TELEMAC wants IPOBO as a permutation of boundary nodes plus a .cli row per node; SCHISM wants gr3 open/land segment blocks. That bookkeeping is telapy's seat. The triangulation + bed elevation at nodes + boundary tags then serialize to .slf / .gr3 / fort.14 / .2dm through the shared writers.

2. Ruled (stands regardless of wiring)

  • One user-facing coastal mesher. No mesher="gmsh" at the registry surface - the edit kernel is an INTERNAL backend of the coastal mesher, tightly coupled, invisible to templates and users. Rev 1's sibling-mesher framing is withdrawn.
  • Checked IO at the kernel seam. The internal boundary is (points, cells, sizing) arrays; every crossing is round-trip verified (node counts, hashes, boundary integrity, IPOBO permutation - the checks the meshers review built).
  • telapy keeps its three proven seats, unchanged: format/boundary authority (the last mile for every TELEMAC mesh, any kernel), adoption of supplied meshes, surgery where regeneration would destroy user work. It is NOT the edit kernel: its punch is non-conformal (80.1 m) and its refine primitives are unfinished - promoting it means maximum reinvention.
  • Session economics (sibling ruling): lazy batched realization, staged-once inputs, snapshot-cache undo - lands for every wiring.

2.1.1 RULED: the (domain, kind) edit-operation matrix - guaranteed at import

A contract table, sibling to ENGINE_MESH_REQUIREMENTS: each (domain, kind) cell declares its edit-operation set. A builder registers FOR CELLS, and registration REFUSES AT IMPORT unless it implements every verb in the cell's set - "guaranteed to work" is unviolable by construction, never checked at call time. A verb not in the cell simply IS NOT OFFERED: never mounted at the gate, never visible to the agent (set_boundary does not exist on a closed catchment, rather than refusing on one). Typed refusal survives only for direct calls to unoffered verbs, naming the cell's actual set. This supersedes both per-mesher action introspection and refusal-as-implementation: selection-by-declaration beats refusal-at-call.

2.1.2 The meshing process, end to end

  1. Declare (frozen, lazy): (domain, kind) validated against the matrix at declaration; the edit set - and therefore the gate's tool list and the form's affordances - known before any build.
  2. Resolve: explicit mesh wins; case-discovered artifacts (filtered by domain/kind/for_ compat) offered; else the declared spec builds the default.
  3. Build (demand-pulled): router auto-selects the cell's builder (coastal-tri -> om2d pipeline, river -> corridor_tin, catchment -> watershed, structured -> reg_grid); inputs staged once; probes + wireframe snapshot.
  4. Gate (USER-GATED; AUTO inline): editable MDAL layer; exactly the cell's verbs mounted as generated tools; edits journal into the recipe; REGENERATE-ON-EDIT as the economical common path; restart truncates to the declared prefix; accept() enforces the for_ contract.
  5. Formats: for_-narrowed writers; telapy last mile; display face through emission.
  6. Artifact: MeshArtifact + recipe + probes -> author -> solve, unchanged.

Doability: modest - the landed registry already carries per-mesher actions and fields. Delta: the domain axis (reshaping the already-ruled capability param), the matrix table + import-time enforcement, auto builder selection in the existing router. Rides the follow-up wave with for_, the session polish, and the rename - one coherent landing after the current wave closes.

2.2 RULED: the for= consumer declaration

for= names the upstream consumer(s) - the engine(s) that will solve on this mesh - and binds the session to their requirements profile (the existing ENGINE_MESH_REQUIREMENTS registry, read at BUILD time instead of only at the consume gate):

  • declaration-time refusal: for="swan" + unstructured refuses before anything builds;
  • adaptive edits: set_boundary under telemac drives .cli/LIHBOR; under schism enforces contiguous gr3 segments + min open-node counts;
  • live readiness: probes carry "solve-ready for <engine>: yes/no + why" DURING editing;
  • accept() is a contract: refuses unless the declared engine's requirements hold - wrong-water-body, non-contiguous segments, missing bed all die inside the session;
  • writers: the declared engine's format is guaranteed, unneeded formats skipped (display face always);
  • defaults painless: templates AUTO-INJECT for= from their own engine; standalone takes it optionally, LIST-valued (for=["telemac","schism"] - one mesh, two engines); omitted = today's generic best-effort + consume-time check.

3.pre DEFERRED design record: patch-local edits

3.0 Wiring C (deferred primary candidate): om2d builds, the kernel patch-edits in place

The om2d mesh exists as the base, built ONCE and held in the prefix-keyed snapshot cache. An edit is PATCH-LOCAL: carve the region around the edit, hand gmsh the patch as a planar polygon with its boundary nodes FIXED, embed the obstacle outline (or size field) inside, re-mesh the patch, stitch back.

  • In place, literally: outside the patch the base mesh is byte-identical, not equivalent.
  • Conformal by construction inside the patch: embedding on a planar surface is gmsh's front door; the discrete classify/reparametrize fragility mostly evaporates on flat 2D.
  • Replay identity restored: base nondeterministic ONCE then cached; edits replay deterministically on the cached base (pinned gmsh version + seed, fixed patch boundary). Recipe replay = cached base + deterministic patches = the same mesh.
  • Caveats, both testable in a prototype: patch-seam quality (min-angle at the stitch boundary goes in the probes, measured); the carve-and-stitch machinery is custom plumbing - scoped and well-defined, but ours.

Prototype gate before commitment - TWO vehicles, same measurements, same Duck NC base mesh, MATLAB remesh_patch semantics as the reference: (1) gmsh planar patch with embedded outline; (2) OCSMesh remesh_by_shape (if its jigsawpy backend resolves in the mesh image at all - an environment failure is itself a disqualifying measurement). Gates per vehicle: seam min-angle, outline offset 0.0 m, 3-run determinism hash, and install/runtime friction recorded honestly. Measurements pick the vehicle.

3.1 The decision rule

  • C (primary) commits if the patch prototype passes its three measurements: seam min-angle acceptable, embedded-outline offset 0.0 m, patch rebuild deterministic (3-run hash).
  • B takes over if the prototype disappoints AND the landscape report shows gmsh-coastal generation (seamsh practice) is walked enough to trust.
  • Fallback if both fail: om2d regenerate-on-edit with the economics fix (lazy batching + snapshot cache) - correct, merely slower.
  • Either way: the registry surface, session, recipe, gate, telapy seats, and shared writers are identical - the choice is invisible above the kernel seam.
