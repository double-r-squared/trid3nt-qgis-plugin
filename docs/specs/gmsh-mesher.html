2. How meshing works (primer)

  • Quality = triangle shape (minimum angle) + sizing h(x), the target-edge-length field. Coastal sizing functions (distance-to-shore, wavelength, bathymetric gradient, gradation) are oceanmesh's specialty and permanent seat.
  • Generation: DistMesh relaxation (oceanmesh - iterative, measured nondeterministic), Delaunay/frontal insertion (deterministic orders possible), structured grids (trivially deterministic).
  • Conformality: an outline is conformal when its vertices ARE mesh nodes; constraints feed INTO generation (retrofit measured 80.1 m offset) - why "edit" means "regenerate" across the field.
  • Cost: nodes ~ area/h²; screening meshes regenerate in seconds - regeneration is the economical common path; patch-local editing stays a deferred design for measured large-mesh pain.
  • Boundaries: contiguous OPEN vs LAND stretches; IPOBO permutations, .cli rows, gr3 blocks - telapy's bookkeeping seat, the last mile for every mesh.

AMENDMENT 2026-09-01 (appended; the bullet above stands as written): "oceanmesh - iterative, measured nondeterministic" is superseded. The drift was not DistMesh's relaxation but feature_sizing_function's skeletonization, which breaks ties through skimage's medial_axis from a generator created fresh per process. Seeding that generator from the recipe's own seed makes the sizing lattice, and the mesh, reproduce: om2d registers deterministic=True, measured as 5 rebuilds from one config returning one mesh on a shoreline-cut coastal domain and a feature-sized harbour domain both. See om2d_driver._seed_library_randomness.

3. The data model (ruled)

  1. The AOI is a DECLARATION - required and defaulted. An explicit declared param (geocode or canvas fills the default), visible in every template, USER-EDITABLE: moving or redrawing the box is legitimate and the containment rule prices it.
  2. Tools all the way down. Fetchers, processing operations, the mesh builder and workflows share ONE invocation substrate - declarable in templates AND directly invocable in chat. The real !run shape (unchanged): !run tool(kwarg=literal, ...) or !run tool {"k": v} - literals only, positional rejected, dispatched as TOOL_REGISTRY[name].fn(**args).
  3. Derived values are named and passed explicitly. Explicit parameters ARE the dataflow - visible at the call site, journaled, nothing hidden, nothing aggregated (the grounding-record draft stays REJECTED). The reach dissolves into named values (flowline, seed, discharge) with coupling by dataflow; a gate-drawn value and a fetched value are the same argument.

3.1 The containment rule

An extent change is judged by GEOMETRIC CONTAINMENT against the STAGED COVERAGE. Within coverage: CROP - a cheap journaled set_extent edit; fetched inputs stand. Outside coverage (moved, or even slightly larger): RESTAGE - not an edit; the change escalates to the rerun primitive with the new bbox, which recomputes the invalidation cut and re-resolves from the beginning. Containment is BINARY (partial coverage produces silently wrong edges). Staging buffer: PENDING NATE - not chartered.

4. The mesh declaration (ruled)

MESH = tool.build_mesh(
    extent = P.aoi,                # ALWAYS declared in templates - one free line,
                                   #   context visible; a derived value narrows in plain sight
    kind   = "unstructured_tri",   # real vocabulary: structured_grid | unstructured_tri | graded_cells
    mesher = "om2d",               # EXPLICIT, never auto - the builder is a deliberate choice.
                                   #   roster: coastal_edge, corridor_tin, hecras_rog, om2d,
                                   #           reg_grid, telapy_mesh, watershed
    for_   = "telemac",            # consumer contract - auto-injected in templates
    shoreline = D.shoreline,       # constituents: ordinary data refs, DATA-first;
    refine = {"edge_length": P.edge_length, "min_spacing": 25},
)                                  # NOTE: no bed= on corridor_tin - a corridor is bed-less
                                   #   by construction; the deck fits elevation at authoring
  • Capabilities from presence: bare extent -> refine_region/apply_layer_edits; + shoreline -> add_obstacle/set_boundary; + flowline -> corridor verbs; + pour_point -> closed catchment. Unoffered verbs never mounted; direct calls refuse naming the missing constituent.
  • Clear-safety by construction: recipe = SPEC LINE (compat-bearing) + EDIT CHAIN; restart truncates the chain only. accept() enforces the for_ contract; the compat gate re-checks at consume.
  • D-2 (ruled - the code's shape is the spec): the mesh build is an EXPLICIT NAMED PLAN STEP, visible in the plan and journaled - not a hidden demand-pull off ops.author. Explicit hops are the model.
  • D-3 (ruled - must fix): template mesh steps read the declaration WHOLE - mesher, kind, AND the declared .edit() chain as the recipe prefix - never reconstruct it. A declared edit silently dropped is the defect class this kills.
  • D-4 (ruled - dropped): no wireframe-PNG vision channel; probes carry the numbers. Revisit only when agent-in-the-loop gate editing matters.

5. The session (ruled)

  1. D-1 (ruled): ALL meshes are editable. Every declared MESH routes through the tool and can open a session - a regular grid has set_extent/set_resolution at minimum. The four reg_grid templates join the session path; the declaration is never a mere deck-keyword carrier.
  2. Resolve: explicit mesh wins; D-9 (ruled): DISCOVERY is wired to the gate - compatible case meshes (compat-filtered, extent-checked, found via the stash and the durable sidecars) are OFFERED by name; declining builds the declared default. The offer's exact tell-vs-silent detail for incompatible finds stays an open discussion, deliberately un-specified.
  3. Build (lazy in-session): inputs staged ONCE; probes out; regenerate-on-edit is the common path; snapshot cache returns the exact previously-inspected mesh per recipe prefix.
  4. Gate (USER-GATED; AUTO inline, and AUTO never adopts a discovered mesh silently): offered verbs mounted as generated tools; the param-sheet revision channel carries numeric AND string-choice knobs per INPUT; geometry-valued inputs enter BY NAME (the server-side name -> case layer -> geometry seam; the polyline IS the selectable boundary structure); hand-edits re-enter via apply_layer_edits, and accept() implies STAGEABLE (D2: regenerate solver files or the edit refuses at the gate).
  5. Formats + artifact: for_-narrowed writers; telapy last mile; display face through emission; recipe = the record with MEASURED determinism flags.
