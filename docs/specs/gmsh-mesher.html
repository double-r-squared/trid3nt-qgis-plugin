2. How meshing works (primer)

An unstructured mesh is a domain cut into triangles. Quality = triangle SHAPE (minimum angle) + SIZING, a field h(x) of target edge lengths. Everything a mesher does serves honoring h(x) with well-shaped triangles.

  • Sizing functions are coastal domain knowledge - distance-to-shore, wavelength (depth-dependent), bathymetric gradient, gradation cap - and are oceanmesh's real specialty; om2d keeps this seat in every design.
  • Generation families: DistMesh force-relaxation (oceanmesh - organic quality, iterative, hence measured nondeterminism), Delaunay/frontal insertion (gmsh/jigsaw - deterministic orders possible, constraints embed during insertion), structured grids (trivially deterministic).
  • Conformality: an outline is conformal when its vertices ARE mesh nodes (zero offset). Constraints must feed INTO generation; retrofitting into a finished mesh measured 80.1 m offset here. This is why "edit" means "change inputs and regenerate" across the field.
  • Cost: nodes scale as area/h^2 - screening meshes regenerate in seconds (measured 3.5 s end-to-end), so regeneration is the economical common path; only large fine meshes hurt (the deferred patch-local design activates on measured pain).
  • Boundaries: the exterior loop splits into contiguous OPEN stretches (forcing enters) vs LAND; TELEMAC wants IPOBO a permutation + .cli rows, SCHISM wants gr3 segment blocks - telapy's bookkeeping seat.

3. The grounding structure - one domain record, progressively filled

There is one AOI, threaded through everything, and today two plan bindings wrap it: Ref("aoi") (the bare bbox) and Ref("reach") (bbox + flowline + mid-reach seed + carrier discharge at the seed - the supplemental grounding that says where the river is, where a release is valid, and what flow carries it). Same role, split names.

Scheduled refactor: unify them into one GROUNDING record. The bbox contains the basis; fetches fill it in. One structure, always carrying aoi, gaining fields as they land:

grounding
  .aoi          # always present - the bbox (geocode or canvas)
  .bed          # filled by the DEM fetch
  .shoreline    # filled by the shoreline fetch -> water/land partition exists
  .flowline     # filled by NLDI -> river structure exists
  .seed         # snapped onto the flowline -> valid release point exists
  .discharge    # read at the seed -> carrier flow exists
  .pour_point   # -> catchment structure exists

Filled fields ARE the constituents; presence is what unlocks capabilities (section 5) AND scenario validity (a dye release is placeable because seed/flowline exist - the same mechanism grounds mesh edits and release points). Templates keep declaring their fetches in DATA; acquire_domain becomes the builder of this record; the reach/aoi name pair disappears from the surface.

4. The signature

MESH = tool.build_mesh(
    kind   = "unstructured_tri",   # discretization - defaulted when obvious
    mesher = "auto",               # builder auto-routed from the constituents; pin to override
    for_   = "telemac",            # consumer contract - auto-injected in templates
    aoi    = P.aoi,                # threaded, like every tool
    bed    = D.dem,                # constituents: ordinary data refs
    shoreline = D.shoreline,
    # flowline = D.rivers,
    refine = {"edge_length": P.edge_length, "min_spacing": 25},
)

# the common path - a place and whatever is true about it:
tool.build_mesh(aoi=aoi, shoreline="fetch:gshhs_shoreline")
  • No words that imply. There is no domain label anywhere: "coastal" is not a thing you say, it is a thing that is TRUE when aoi + bed + shoreline are present.
  • Frozen and lazy in templates (a declaration block beside DATA and PARAMS; builds nothing at import; demand-pulled). Standalone it builds now and stashes for case discovery.
  • Sourcing is DATA-first in templates (declared ladders, gate visibility, journaling); in-tool "fetch:" specs are standalone sugar through the SAME fetch router - one seam, two spellings. Staged-once session economics make them equal in cost.
  • for_ binds the session to the consumer's requirements (the existing ENGINE_MESH_REQUIREMENTS, read at build time): declaration-time refusals, consumer-adaptive edits (.cli/LIHBOR vs contiguous gr3 segments), live "solve-ready" probes, accept() as a contract, writers narrowed to the declared engine + display. List-valued for one mesh feeding two engines.

5. Capabilities derive from presence

the grounding carrieswhich offers
bare aoia grid over the box; refine_region, apply_layer_edits
+ shorelinewater/land partition -> add_obstacle, set_boundary
+ flowlinecorridor verbs; valid release areas
+ pour_pointcatchment behavior: closed boundary; set_boundary never appears

The ONLY capability mechanism. Unoffered verbs are never mounted at the gate and never visible to the agent; a direct call to one refuses by naming the missing constituent ("add_obstacle needs a water/land partition; supply a shoreline") - the error and the onboarding hint are the same sentence, and capabilities disclose progressively as the user defines more. Builders register per CONSTITUENT PATTERN; registration REFUSES AT IMPORT unless every verb the table offers for that pattern is implemented - guaranteed by construction, never checked at call time.

6. The session

  1. Declare: constituents named; the capability set - the gate's tool list, the form's affordances - known statically before any build.
  2. Resolve: explicit mesh wins; case-discovered compatible artifacts offered; else the declaration builds.
  3. Build (demand-pulled): the router selects the builder for the constituent pattern; inputs staged ONCE and reused by every rebuild; probes + wireframe snapshot out.
  4. Gate (USER-GATED; AUTO builds inline): editable MDAL layer; exactly the offered verbs mounted; edits journal into the recipe; REGENERATE-ON-EDIT is the common path (economical at common sizes); restart truncates to the declared prefix; the snapshot cache returns the exact mesh previously inspected for any prefix (session-stable despite generator nondeterminism); QGIS hand-edits re-enter as apply_layer_edits with the layer hashed, honestly non-replayable; accept() enforces the for_ contract.
  5. Formats + artifact: for_-narrowed writers, telapy last mile (IPOBO permutation, contiguous .cli, gr3 blocks), display face through emission; MeshArtifact + recipe + probes into author -> solve, unchanged.

The recipe is the record: spec line + ordered edits, journaled; deterministic flags are MEASURED claims per builder; replay = exact from the snapshot cache in-session, equivalent rebuild cold.

7. Scheduled refactors (the follow-up wave, in order)

  1. The GROUNDING record (section 3): acquire_domain builds it; Ref("aoi")/Ref("reach") dissolve from the surface; seed/discharge consumers read the record.
  2. Constituent rule table + import-time pattern enforcement, replacing per-mesher field validation.
  3. Builder auto-routing (mesher="auto").
  4. for_ consumer contract.
  5. Session polish: staged-once inputs, prefix-keyed snapshot cache, lazy batched realization.
  6. MESH declarations in the 7 templates take the constituent surface (small diffs; deck parity must hold).

HELD until the mesh wave closes clean and NATE releases the hold. Deferred separately, recorded: patch-local edits (gmsh planar patch vs OCSMesh remesh_by_shape, MATLAB remesh_patch precedent) - activates on measured large-mesh pain only.
