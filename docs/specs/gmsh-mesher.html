2. How meshing works (primer)

  • Quality = triangle shape (minimum angle) + sizing h(x), the target-edge-length field. Sizing functions (distance-to-shore, wavelength, bathymetric gradient, gradation cap) are oceanmesh's specialty and its permanent seat.
  • Generation: DistMesh relaxation (oceanmesh - iterative, measured nondeterministic), Delaunay/frontal insertion (gmsh/jigsaw - deterministic orders possible, constraints embed during insertion), structured grids (trivially deterministic).
  • Conformality: an outline is conformal when its vertices ARE mesh nodes. Constraints must feed INTO generation (retrofit measured 80.1 m offset here) - the structural reason "edit" means "regenerate" across the field.
  • Cost: nodes ~ area/h²; screening meshes regenerate in seconds (measured 3.5 s end-to-end) - regeneration is the economical common path; patch-local editing stays a deferred design for measured large-mesh pain.
  • Boundaries: contiguous OPEN stretches vs LAND; IPOBO permutations, .cli rows, gr3 blocks - telapy's bookkeeping seat, the last mile for every mesh.

3. The domain model (discussion-stage - NATE's proposal, awaiting his freeze)

Derive, never override. The domain is the base spatial extent - the bbox from geocode or canvas - and it is IMMUTABLE and always reachable. Specialized extents are DERIVED from it as their own named values; nothing is lost, nothing aggregates:

domain   = bbox                                  # the base - never overridden
basin    = delineate(domain, pour_point)         # derived subdomain (terrain's answer)
corridor = corridor_of(domain, flowline, width_m=200)
county   = clip(domain, admin_polygon)

MESH = tool.build_mesh(aoi=basin, bed=D.dem, ...)  # mesh EXACTLY the area of interest
  • No over-meshing, no hand-authoring: the mesh gets the basin, not the box around it.
  • Fetch-wide, mesh-narrow: fetches stage over domain once; meshing consumes the subdomain; a moved pour point re-derives the subdomain with ZERO re-fetch (the wide raster still covers it) - composing with staged-once economics.
  • The base stays reachable for operations needing data outside the subdomain (upstream gauges, context rain, basemaps); multiple subdomains coexist as siblings.
  • Derivation is provenance: each subdomain carries parent + operation + inputs, journal-friendly like the mesh recipe.
  • This is the plan's own law: step results are deep-frozen named values; refs never rebind. The model names what the substrate already does.

3.0 The extent rule - one AOI, mesh-slot default, runtime-only override

There is exactly ONE AOI - threaded through the plan, consumed by every function, never overridden by anything. The mesh slot's extent DEFAULTS to it, and mesh generation is unopinionated over it by the cost asymmetry: over-meshing wastes compute (recoverable); premature narrowing loses correctness (unrecoverable - the missed area is simply absent from the answer).

# templates write NO aoi line at all - the mesh slot reads the threaded AOI.
# there is no syntax by which a workflow can substitute the extent.

# the ONLY override is runtime, ad hoc, at the user's initiative:
session.edit("set_extent", geometry=drawn)   # they ask, or they draw -
                                             # journaled, basis=user, restart-able,
                                             # narrow OR widen
  • Why no workflow-level override: a declared aoi=basin buried in a MESH slot is hidden undefined behavior - the user fed an AOI, every other consumer reads it, and the mesh silently consumed something else. The divergence is invisible on the surface. Forbidden by construction: the slot has no extent parameter in templates.
  • Delineation-shaped questions stay legal as the MESHER'S DECLARED BEHAVIOR, not a slot substitution: pour_point present means "the terrain that drains to this point" IS the question, stated visibly in the declaration - and the derived extent is PRESENTED at the gate, where the user sees exactly what got meshed and can override at runtime. Declared-and-presented derivation: legal. Silent substitution: forbidden. Runtime user override: the one path.
  • Polymorphic and provenance-labeled: the threaded bbox, a mesher-derived extent, and a drawn geometry are the same type to generation; the slot records which filled it (default / mesher-derived / user).
  • Fetch-wide holds under every case: staging happens over the threaded AOI regardless - runtime overrides never re-fetch.
  • Derived subdomains (section 3) remain first-class values for NON-mesh consumers - reporting clips, charts, sampling - where naming an extent is explicit dataflow, not substitution.

3.1 Inputs live in ONE place - no bundles, no records

Constituents (bed, shoreline, flowline) are ordinary DATA refs passed explicitly to what needs them - singly homed, plain in-and-out, no aggregating transport. (An earlier "grounding record" draft was REJECTED for making inputs live in two places.) The reach bundle DISSOLVES into named plan values with the coupling preserved by dataflow, not structure:

flowline  = fetch(domain)            # where the river is
seed      = snap_to(flowline)        # a valid release point exists
discharge = read_at(seed)            # the carrier flow exists

# each consumer names exactly what it needs:
mesh(aoi=corridor, flowline=flowline)   # meshing
forcing(carrier=discharge)              # forcing
release_gate(valid_on=flowline)         # scenario validity

A gate-drawn value and a fetched value are the same argument - no operation cares who authored its inputs.

4. The signature

MESH = tool.build_mesh(
    kind   = "unstructured_tri",   # discretization - defaulted when obvious
    mesher = "auto",               # builder auto-routed from the constituents; pin to override
    for_   = "telemac",            # consumer contract - auto-injected in templates
    aoi    = basin,                # the extent THIS mesh covers (domain or any subdomain)
    bed    = D.dem,                # constituents: ordinary data refs
    shoreline = D.shoreline,
    refine = {"edge_length": P.edge_length, "min_spacing": 25},
)
  • No words that imply: no domain labels anywhere - "coastal" is TRUE when aoi + bed + shoreline are present, never said.
  • Frozen and lazy in templates (a declaration beside DATA and PARAMS); standalone it builds now and stashes for discovery.
  • DATA-first sourcing; in-tool "fetch:" specs are standalone sugar through the same router.
  • for_ reads ENGINE_MESH_REQUIREMENTS at build time: declaration-time refusals, consumer-adaptive edits, live solve-readiness probes, accept() as a contract, writers narrowed. List-valued.

Builders register per constituent pattern; registration refuses at import unless the pattern's verbs are implemented.
