1. The principle

A mesh is defined by exactly one object: its RECIPE - the current program that produces it. Present tense, editable, executable.

mesh state = recipe + staged inputs
recipe     = three agnostic params + one ordered ops list

There is no record, no history object, no edit-op chain: the journal (append-only by law, already existing) captures edit events as audit; undo is editing the recipe back; the one structured revert is reset-to-declaration. Same recipe + same staged inputs = same mesh. Every change regenerates wholesale (measured cheap); nothing is patched incrementally. accept() freezes the recipe onto the artifact as its provenance.

2. The surface

build_mesh takes the mesher, the element kind, and exactly THREE mesher-agnostic parameters - extent (the domain), resolution_m (the size word), kind - plus the program. Nothing else. Engine vocabulary (bed, boundaries) is NEVER a parameter of the generalization: those are ops.

MESH = tool.build_mesh(
    mesher="om2d", kind="unstructured_tri",
    extent=reach, resolution_m=P.mesh_resolution_m,
    ops=[
        # oceanmesh's own functions - verbatim names, explicit data args
        mesh_op("feature_sizing_function"),
        mesh_op("distance_sizing_from_linestring_function", line=DATA.centerline, rate=0.05),
        mesh_op("enforce_mesh_gradation", gradation=0.15),
        mesh_op("delete_boundary_faces"),
        # our registered primitives - verbatim def names, SET verbs
        mesh_op("set_bed", source=DATA.topobathy, interp="nearest"),
        mesh_op("set_boundary_roles", inflow=reach.face_start, outflow=reach.face_end),
    ],
)

ONE flat ordered list - no pre/post subtypes. The op vocabulary has TWO ORIGINS, both verbatim: the wrapped library's functions under the library's names, and our registered primitives under their real def names - never aliases (an alias is a word that implies). State-imposing primitives use the set verb: set_bed, set_boundary_roles. Phase (before or after generation) is DERIVED from the namespace registration; declared relative order is preserved within each derived phase; a name present in both origins refuses loudly. Omitting ops takes the mesher's hard-baked, VISIBLE default list; declaring replaces it wholesale. resolution_m keeps the one documented default-threading rule (default min_edge_length, max_el defaulting 10x) - overridable per entry, a changed default said out loud.

The LLM-refinement loop is this tool and nothing more: "tighten resolution along the channel" is the model appending an op. The recipe is the conversation's accumulating artifact; the user building their own mesh authors a recipe entry-by-entry through whichever door they like.

4. Validation: the signature is the schema

MeshField dies. Generic validation for every mesher and every origin: (a) the name exists in the registered namespace; (b) the kwargs bind to the real callable's signature (inspect.signature(...).bind_partial); (c) a data-valued kwarg (a DATA row, a layer handle) passes through the one typed conversion layer - explicit kinds (raster -> array, layer -> geometry), kept small and visible, never guessed. A function without an introspectable signature passes through with a journaled note; the library's own error surfaces verbatim on failure (the upstream-errors law).

5. The correct-data-class law

An op takes the data class it is DEFINED OVER; acquiring that class is the DATA row's problem (ladders, supply paths, honest refusals) - the op assumes its input is good and carries no class-policing branches. set_bed(source=DATA.topobathy) - never a silent DEM proxy: a standard DEM measures the water surface, not the channel bottom, and every shim that ever compensated for that substitution (the deleted fit_downstream_bed) was scar tissue over the wrong input. A substitution is legitimate only as the AUTHOR'S visible declared choice (set_bed(source=DATA.dem) written in the recipe), and the journal names the source row painted from - transparency by record, not by machinery.

Companion NO-NAME-DRIFT law: fetched rows carry the DATASET's name (topobathy, water = fetch_nhd_area_water); derived rows carry what they ARE (window, reach). One datum, one name, everywhere - name drift is implementation drift with a delay. Renames owed by this spec: banks -> water; measure_bank_coverage -> measure_water_coverage.

CHARTERED (paper-first, its own item, not this wave): bathymetry research - fetch_topobathy coverage per water-body class, surveyed cross-sections as a supply path, synthetic-channel methods only ever as a declared PRODUCER row, never a shim.

Hand-edits at the gate (dragging nodes) are the one operation that is genuinely history rather than program: they flag the artifact "regen breaks this" instead of being pretended into the recipe.

7. What a mesher IS

registrationcontent
namespacethe library module(s) whose function names ops may use, tagged by phase; the SHARED primitives namespace (set_bed, set_boundary_roles, ...) rides along for every mesher
role adapterhow extent becomes this library's domain object; how resolution_m/max_el thread as its defaults. Nothing else - an adapter that grows opinions is the old sin
default recipethe hard-baked visible ops list an undeclared ask gets

Everything else - validation, recipe machinery, mesh_op, the gate's generic cards, regen, the artifact - is shared. reg_grid CONFORMS: same surface, near-empty default recipe. A new mesher is three registrations and the router never grows.
