Render and the Engine File

rev 1a · 2026-09-12 · render accepts a format set and an engine carries one transform; one file per engine over one executor; derive narrowed to simulation automation with QGIS's own algorithms and PyQGIS run in the user's session; the attics. The wave after the module-is-the-unit wave.

1. Render: a format set, a default style, a transform per engine

The package that turns data into what the user sees is named render (it is emission today). It accepts exactly what QGIS opens and nothing else: a raster as a COG, a vector as GeoJSON, GPKG or FlatGeobuf, a mesh in any MDAL format (SELAFIN, 2dm, UGRID, HEC-RAS 2D HDF), a series or a profile as a chart payload. Each arrives with the style row declared beside the product that draws it (kind, ramp, units, floor, range cap); the default style carries the weight. A user's restyle is the edit of a style, kept beside the presets as its own seam. An engine whose output is not in the set carries ONE transform module beside its module surface that normalizes it; an engine whose output is in the set carries none.

3. Derive: simulation automation only; QGIS does the rest in the session

A derive tool exists to automate the simulation process for the supported engines: domain geometry, observation pairing and skill, the analytic models the templates overlay, point reads, restyle. Each takes a layer and returns a layer or a value; none fetches. The thirteen tools that reimplement QGIS and GDAL algorithms in numpy (hillshade, slope, aspect, contours, clip, NDVI, colored relief, blended composite, change detection, impervious surface, landcover class, building density, satellite enhance) leave for the attic as one set. In their place, two generic registered tools executed in the user's QGIS session through the plugin wire:

tooldoesgate
run_qgis_algorithm(algorithm, params)the plugin runs processing.run in the session over named canvas layers and adds the output to the project; the layer summary comes backnone; the Processing Toolbox runs unasked over the user's own layers
run_pyqgis(code)the plugin executes the code in the session's Python and returns its resultthe existing code-execution approval card; ConsequentialCodeIsUserGated holds

No algorithm corpus, no ranker, no sequence machinery: the model knows the basic algorithms and PyQGIS, and the docstrings point at the QGIS processing reference. The model fetches, and when the layer exists, runs the algorithm. Every other corpus stays as it is. The container sandbox and its code-exec tool retire to the attic; the session is the one code path.
