The Module Is the Unit

rev 2 · 2026-09-10 · parts leave the surface: vertical generalization only, the reach chain as one primitive. The engine's module is the unit the system is built around; a scenario is expressed over it, never built and then tied to it. The small refactor wave before calibration.

1. The principle

An engine exposes modules (TELEMAC: telemac2d, telemac3d, artemis, tomawac, with gaia and waqtel coupled). A module has a keyword dictionary, inputs, and outputs. Everything TRID3NT knows how to do with an engine is a capability of one of its modules: a composite that expands one value into keywords, a primitive that reads one thing off a result. A scenario such as a dye plume down a river is a set of values over the telemac2d module plus a list of which primitives to read. Nothing below the template layer may know the scenario exists.

2. Identity: the solver is the engine

One solver registration per engine. The run record carries engine and module; the module is the manifest's own case.module, which the worker already keys on and refuses by name when unknown. The dispatch card reads "TELEMAC / artemis". Code provenance resolves an engine from the record's engine field.

3. The module surface: dictionary, composites, primitives

telemac/catalog/ is renamed telemac/dictionary/ and the Module attribute with it: the engine's own word for the thing. Composites stay as they are. Outputs become primitives named from the module's variable vocabulary; the question-named outputs (dye, oil_slick, agitation, column_structure) leave the wrappers.

Publishing is generic and written once: a field becomes a layer with a style, a series becomes a chart, a field over time becomes an animation. The per-question postprocessors in telemac/products/ dissolve: their private readers become the primitives, their layer and chart calls become the generic publishers, and what is left of each is the template's outputs list. The two postprocessors with no callers (coastal, tomawac) go outright. An analytic reference such as the Streeter-Phelps sag is not an engine output and moves beside the template that overlays it.

    NUMBER_OF_TRACERS = 1                       # the question, in three lines
    NAMES_OF_TRACERS = ["DYE             MG/L"]
    INITIAL_VALUES_OF_TRACERS = [0.0]

                        window_s=R.spill_duration_s)]

ruleconsequence
a template is a body of keywords, DATA rows, an outputs list, captions; nothing elsea template that defines a function, or composes another body, is refused by the lint; the fix is a primitive on the module or ten restated lines
no parts: generalization is vertical onlythe parts mechanism leaves the module surface and templates/shared goes. The RIVER part's reach chain (geocode, seed, flowline, bed, mesh, settled boundary and initial state) becomes ONE primitive in the mesh and authoring layer, reach = tool("river_reach", seed=P.release, aoi=...), one DATA row any template on any engine may call; its RELEASE params move to the templates that release; its ten keyword lines are restated per template. Shared things are engine-agnostic by construction only: typed inputs, the AOI, the reach primitive, publishing
nothing is frozentwo tracers is an override of NUMBER_OF_TRACERS and the names; the tracer composites already take lists
the question and the ask are stated in the template; numerics are engine defaults unless the template states a value with its reasondescribe and the card show set values and open slots; every keyword stays overridable through the sheet
engine defaults are unwritten; an opinion states its reason at the lineruled: the SCHEME_FOR_ADVECTION_OF_TRACERS = 1 line is deleted and the engine default 13 applies; COEFFICIENT_FOR_DIFFUSION_OF_TRACERS and VELOCITY_DIFFUSIVITY are engine defaults below the template, and a template that wants 0.1 states it with its reason

The per-template declarations shrink to the ask: the substance, its concentration, the spill window, the release. Per-template chart builders, coercion modules, and lat/lon spellings go. The measurement point is river_dye re-expressed this way before the other seven move.

A pick carries a name: the plugin offers a field, defaulted to point-n; the wire payload and the run record gain name. The name feeds the tracer name, the source label, and the chart title, so neither the user nor the model supplies it a second time. The slot's role stays in the gate title, because "place the release" is information; the action and the ingestion are not per-thing. What goes: release_lat/release_lon in four templates, release_coords, spill_location_latlon, templates/river_dye/coercions.py, the normalizer special case, and the point-specific halves of helpers/release_point.py and helpers/release_layer.py, which become Point methods.

6. Provenance: one field, a closed vocabulary, read by people

The field is the one that exists on every filled slot; its free text becomes this vocabulary. The card renders it as a chip so a reader can override with confidence. No consumer changes behavior on it: the user or the driver decides. This is the only place the word "template" appears at runtime.

8. The adapters' message IR is ours

Four files (adapters/adapter.py, openai_adapter.py, anthropic_adapter.py, gates/context_budget.py) build turns from six google.genai.types classes: Content, Part, FunctionDeclaration, FunctionCall, FunctionResponse, UnionType. That is a whole provider SDK carried for its data classes. The IR becomes five models in contracts: Message(role, parts), Part(text | call | response), ToolCall(name, args, id), ToolResponse(name, result, id), ToolDeclaration(name, description, schema). Each provider adapter converts from these at its own boundary, which is what each already does from the google classes. google-genai leaves pyproject.toml; a dormant Gemini branch in adapter.py, if the wave finds one, goes to the attic with a manifest.

14. Acceptance

The wave is closed when: no file below the template layer contains a template name or a question word; every wrapper output is a primitive; every template is values; every point in the system is a Point; every filled slot carries one of six origins; the run record carries engine and module; the adapters import no provider SDK for their IR; the dev directory renders a packet and the backup exists; the eight canaries pass with packets rendered under run/proof; the product pure-LOC row is reported against 100,099 with the row's contents restated; the conformance table is read.
