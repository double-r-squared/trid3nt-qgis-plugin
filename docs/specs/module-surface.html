Format per docs/decisions/0320-spec-format.md. Frozen: the mesh recipe (docs/specs/mesh-recipe.html), the emission fold, the worker's engine-room contract, the data seam.

1. The principle

A workflow is a wrapper around a TELEMAC module, exposing the module's FULL keyword surface. The engine already publishes that surface: every module's dico names each keyword, its type, its allowed values, its default and its help text. We stop transcribing it by hand into f-strings and comments. The wrapper is the engine's catalog and NOTHING ELSE that opines; variance lives in templates, which stay Python because they are read by people. Every knob is reachable at invocation. Simple system, complex work.

2. The sheet: a module's keywords are slots

Every keyword in a module is a SLOT. The dico's SUBMIT field marks FILE slots (GEOMETRY FILE, BOUNDARY CONDITIONS FILE, SOURCES FILE, FORTRAN FILE). A slot's value comes from exactly one of the sources below, and the sheet records which - PROVENANCE is shown per slot, so nothing inherited or derived is hidden.

Resolution order, lowest to highest: engine default, shared body, template, fill. At most two opinion layers exist and both are templates. A slot not in the module's catalog refuses by name at import time (template) or at fill time (invocation); a value outside the dico's choices refuses naming the choices.

3. The wrapper: catalog, composites, outputs - no opinion

One wrapper per module under telemac/modules/: telemac2d, telemac3d, artemis, waqtel, gaia (tomawac: see §13). The wrapper holds three things and asserts no value of its own.

# modules/telemac2d.py
T2D = Module("telemac2d")                       # catalog/telemac2d.json -> one Slot per keyword
T2D.composites(releases=Releases, wind=Wind,    # one value stands for several slots (+ the file they name)
               continue_from=Continuation)
T2D.outputs(fields=read_selafin,                # the module's outputs and how each is read
            mass_balance=read_listing_balance)

Coupled modules (WAQTEL, GAIA) are wrappers too; a template names a coupling body (WAQTEL.decay(...), GAIA.erodible(...)) whose slots serialize into the coupled steering file and whose COUPLING WITH / steering-file keywords land on the carrier's sheet.

4. Templates and shared bodies

A template package stays what it is: the recipe file, declarations.py, corpus.yaml. Its recipe file now carries a STEERING body of raw keywords, spelled as identifiers by the mechanical spaces-to-underscores map the image itself ships (eficas <module>_dicoCasEnToCata.py). Every hardcoded author literal becomes a visible assertion here, or an engine default by omission.

# templates/shared/river.py - a shared body: a PART the river templates list
class RIVER(T2D):
    TIDAL_FLATS = True
    OPTION_FOR_THE_TREATMENT_OF_TIDAL_FLATS = 1
    TREATMENT_OF_NEGATIVE_DEPTHS = 2
    SOLVER_ACCURACY = 1e-6
    INITIAL_CONDITIONS = "CONSTANT DEPTH"
    GEOMETRY_FILE = MESH                                  # a file slot, filled by the recipe
    BOUNDARY_CONDITIONS_FILE = MESH.boundaries
    PRESCRIBED_FLOWRATES = derived.inflow(P.discharge_m3s)
    PRESCRIBED_ELEVATIONS = derived.normal_depth_stage()
    INITIAL_DEPTH = derived.normal_depth()

# templates/river_dye/river_dye.py
class STEERING(T2D):
    parts = [RIVER, TRACER]                               # composed in this order; a keyword two parts set refuses unless settled here
    DURATION = P.sim_duration_s
    GRAPHIC_PRINTOUT_PERIOD = derived.steps(P.output_interval_min)
    LAW_OF_BOTTOM_FRICTION = P.friction_law
    FRICTION_COEFFICIENT = P.friction_coefficient
    NUMBER_OF_TRACERS = 1

                        conc=P.dye_concentration_mgl, window_s=P.spill_duration_s)]
    wind = Wind(speed_mps=P.wind_speed_mps, from_deg=P.wind_direction_deg)
    coupling = [WAQTEL.decay(half_life_h=P.decay_half_life_hours)]

THE COMPOSITION LAW (amended 2026-09-04, rev 1b): a shared body is a PART a template lists, never a parent it extends. It lives in templates/shared/, is named for what it is (river, catchment, basin - never reach), is created only when a good portion of a template is shared, and must have at least two users (one user folds back into its template; the suite checks). Parts merge in the listed order; a keyword set by two parts REFUSES by name unless the template settles it itself; a template's own assertion beats any part. Per-slot provenance names the part, so composed context is visible at the use site: a keyword that means something else in a new setting is seen, not assumed. The same mechanism serves a fill-time bundle.

ONE TEMPLATE PER QUESTION (rev 1b): a structural fork of the deck - tracer, oil and sediment fill DIFFERENT slots, not different values - is a different template, never a switch on a param. river_dye = RIVER + TRACER; river_oil_spill = RIVER + OIL; river_sediment = RIVER + SEDIMENT (+ the dredging composite); do_sag = RIVER + O2. Bodies are static and read no resolved value. Optional features within one question are composites that state nothing when given nothing (a decay rate, dredging, a hyetograph versus a constant rate). The tool surface is seven templates; routing picks the template.

PARAMS are unchanged in shape (Param(desc=..., default=..., bounds=..., units=...)); a slot's desc is the dico's help, so a raw keyword reads to the LLM and the human exactly the way a Param does. Physics(...) and Forcing(...) no longer exist; a forcing series is a file-slot producer.

5. Fill, then run

The plan language dissolves into two acts on one sheet. Execution is HELD until the user runs.

callcontract
fillRepeatable. Accepts template params, canvas points, and a validated keywords={RAW: value} floor. Producers run during fill so the canvas shows the mesh and the release before any solve. Returns the sheet: every filled slot with provenance; every open mandatory slot with its desc, choices and engine default.
runExplicit, on a complete sheet only. Serializes, stages the rundir, hands it to the box. Step-through and reentry are the landed rerun machinery, unchanged.
describe_keywordsRead-only: "what governs friction" answered from the catalog - help, labeled choices, engine default, level, file-ness. The way the LLM reaches the 1,311-keyword surface the docstring budget cannot carry.

A bare module run is the same sheet with nothing pre-filled: engine defaults plus the mandatory slots. "Filled by a template and edited, or filled by hand" is one mechanism.

6. The serializer

One function for every module: resolve the sheet, assign each keyword into telapy's TelemacCas (in-image, the existing driver pattern), write, re-parse. The re-parse is where the dico's choices are enforced; cas_validate's round trip stays as that gate. Two measured caveats are handled inside the serializer, nowhere else: file keywords are assigned through cas.values[...] (telapy's set() demands the file exist), and string values are handed to telapy as a str subclass whose __repr__ is the engine's own form - a single-quote delimiter with '' inside - because telapy's write() formats with repr() and Python's repr switches to a double-quote delimiter the engine cannot read (Stage 0 measured all four spellings against the box; only 'Nate''s reach' runs). telapy still writes the file; only the delimiter is ours. The engine reads the written file; there is no second serialization path.

def serialize(module, sheet, rundir):
    cas = TelemacCas(path, get_dico(module.name), access="w")
    for keyword, value in sheet.resolved():        # engine defaults are NOT written; the dico supplies them
        cas.values[keyword] = escape(value)
    cas.write(path)
    validate_authored_steering(rundir, {path.name: module.name})
