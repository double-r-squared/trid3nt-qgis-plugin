The Module Surface

Frozen: the mesh recipe (docs/specs/mesh-recipe.html), the emission fold, the worker's engine-room contract, the data seam.

1. The principle

A workflow is a wrapper around a TELEMAC module, exposing the module's FULL keyword surface. The engine already publishes that surface: every module's dico names each keyword, its type, its allowed values, its default and its help text. We stop transcribing it by hand into f-strings and comments. The wrapper is the engine's dictionary and NOTHING ELSE that opines; variance lives in templates, which stay Python because they are read by people. Every knob is reachable at invocation. Simple system, complex work.

2. The sheet: a module's keywords are slots

Every keyword in a module is a SLOT. The dico's SUBMIT field marks FILE slots (GEOMETRY FILE, BOUNDARY CONDITIONS FILE, SOURCES FILE, FORTRAN FILE). A slot's value comes from exactly one of the origins below, and the sheet records which - PROVENANCE is one field on every filled slot, a closed vocabulary the card renders as a chip, so nothing inherited or derived is hidden. The engine default answers by absence and carries no row.

origindetailmeaning
templatethe template's namea starting value
usertyped or confirmed by the user, a canvas pick among them
modelproposed by the LLM during the fill
producerthe producer's namecomputed at fill time from fetched data - the mesh recipe, a DATA row, a composite's file
derivedthe source slotexpanded from another slot by a composite, or measured by the assembler off the accepted artifact (boundary order, normal-depth stage, Z(Q))
calibratedthe calibration run idfrom a proposal the user confirmed

Resolution order, lowest to highest: engine default, template, fill. One opinion layer exists and it is the template. A slot not in the module's dictionary refuses by name at import time (template) or at fill time (invocation); a value outside the dico's choices refuses naming the choices.

3. The wrapper: dictionary, composites, primitives - no opinion

One wrapper per module under telemac/modules/: telemac2d, telemac3d, artemis, waqtel, gaia (tomawac: see §13). The wrapper holds three things and asserts no value of its own.

# modules/telemac2d.py
T2D = Module("telemac2d")                       # dictionary/telemac2d.json -> one Slot per keyword
T2D.composites(releases=_releases, wind=_wind,  # one value stands for several slots (+ the file they name)
               continue_from=_continuation)
T2D.outputs(**PRIMITIVES, drogues=_drogues)      # the primitive set, plus what this module alone writes
T2D.VARIABLES = {"U": ..., "H": ..., "T": ...}    # the module's own variable vocabulary
partisis not
dictionarythe dico, extracted once in-image into telemac/dictionary/<module>.json (committed; a suite test re-extracts from the image when present and fails on drift) - the engine's own word for the thingedited by hand; opined on
compositesexpanders for repetitive, failure-prone keyword groups - a composite may set ONLY what its value's presence defines (the arming keyword its input implies, the slots its value literally fills); a choice among alternatives is a template assertion or the engine default: a Release becomes ABSCISSAE/ORDINATES/DISCHARGE/VALUES OF THE TRACERS AT THE SOURCES plus the sources series; wind becomes the five wind keywords with the from-direction transform; continuation becomes PREVIOUS COMPUTATION FILE + the staged input, the FORMAT it is read at being one of the three the dictionary offers and so the template's; degradation, gradation (four parallel CLASSES lists), dredging (NESTOR keywords + three files), oil (preset + patched Fortran)a place for defaults; a template's private code
primitivesthe outputs, named from the module's variable vocabulary and nothing else: field(name, t), series(name, at), max_over_time(name), profile(name, along), extent(), mesh(), mass_balance(), plus what one module alone writes (TELEMAC-2D's drogues(), TELEMAC-3D's column()); a token a module DEFINES over its own result (ARTEMIS's KD) reads as any variable. Publishing is generic and written once under workflows/publishing/: a field becomes a layer, a series a chart, a field over time an animationa reader that knows a question; a question-named output

Coupled modules (WAQTEL, GAIA) are wrappers too; a template names a coupling body (WAQTEL.degradation(...), GAIA.bed(...)) whose slots serialize into the coupled steering file and whose COUPLING WITH / steering-file keywords land on the carrier's sheet, and GAIA's primitives read its own result file.

4. Templates are values

A template package is the recipe file, declarations.py, corpus.yaml. The recipe is VALUES over one module: a STEERING body of raw keywords spelled as identifiers by the mechanical spaces-to-underscores map the image itself ships (eficas <module>_dicoCasEnToCata.py), the DATA rows it consumes, the MESH recipe, an OUTPUTS list of primitives with how each is published, CAPTIONS and an ANSWER of measures. Every author literal is a visible assertion here, or an engine default by omission. A template defines no function and composes no other body; the lint under dev/lint/ refuses one that does.

# templates/river_dye/river_dye.py
class STEERING(T2D):
    GEOMETRY_FILE = "river.slf"; BOUNDARY_CONDITIONS_FILE = "river.cli"; RESULTS_FILE = "r2d_river.slf"
    TIME_STEP = Ref("settled.time_step_s"); INITIAL_CONDITIONS = "CONSTANT DEPTH"; INITIAL_DEPTH = Ref("settled.depth_m")
    LAW_OF_BOTTOM_FRICTION = Ref("settled.friction_law")   # the river lines every river deck states, restated here
    NUMBER_OF_TRACERS = 1                                     # the question, in three lines
    tracer_names = TracerNames(names=["DYE             MG/L"], named_by=Ref("release.name"))
    INITIAL_VALUES_OF_TRACERS = [0.0]
    boundaries = Boundaries(measured=Ref("settled"), tracers=[0.0])
    releases = [Release(at=Ref("release.at"), q=P.source_q_m3s, tracers=[P.dye_concentration_mgl],
                        window_s=P.spill_duration_s, until_s=Ref("settled.until_s"))]

OUTPUTS = [field("T1", t="every").animate(), max_over_time("T1").layer(), series("T1", at=DATA.release).chart()]
CAPTIONS = {"T1": "{substance} concentration"}

NO PARTS: generalization is vertical only. A value two templates share is restated in each, under the template that states it, so a keyword that means something else in a new setting is seen at the use site; per-slot provenance names the template. The one exception is a DATA row two or more templates read: the reach rows the river templates share live in templates/reach.py, and a template names them. Nothing is frozen - two tracers is an override of NUMBER OF TRACERS and the names on the fill, and the tracer composites take lists.

ONE TEMPLATE PER QUESTION: a structural fork of the deck - tracer, oil and sediment fill DIFFERENT slots, not different values - is a different template, never a switch on a param. The rule holds at every level: a fork that fills different slots is a template, never a composite that owns a carrier slot. Bodies are static and read no resolved value. Optional features within one question are composites that state nothing when given nothing (a degradation rate, dredging, a hyetograph versus a constant rate). The tool surface is eight templates; routing picks the template.

The question and the ask are stated in the template; numerics are engine defaults unless the template states a value with its reason at the line. PARAMS are unchanged in shape (Param(desc=..., default=..., bounds=..., units=...)); a slot's desc is the dico's help, so a raw keyword reads to the LLM and the human exactly the way a Param does. A point a template asks for is a Point slot under its role name (release, outfall, pour), fed by the pick, a pair, a point layer or a geocoded name, and the name it carries is the tracer's.

5. Fill, then run

The plan language dissolves into two acts on one sheet. Execution is HELD until the user runs.

callcontract
fillRepeatable. Accepts template params, canvas points, and a validated keywords={RAW: value} floor. Producers run during fill so the canvas shows the mesh and the release before any solve. Returns the sheet: every filled slot with provenance; every open mandatory slot with its desc, choices and engine default.
runExplicit, on a complete sheet only. Serializes, stages the rundir, hands it to the box. Step-through and reentry are the landed rerun machinery, unchanged.
describe_keywordsRead-only: "what governs friction" answered from the dictionary - help, labeled choices, engine default, level, file-ness. The way the LLM reaches the 1,311-keyword surface the docstring budget cannot carry.

A bare module run is the same sheet with nothing pre-filled: engine defaults plus the mandatory slots. "Filled by a template and edited, or filled by hand" is one mechanism.

6. The serializer

One function for every module: resolve the sheet, assign each keyword into telapy's TelemacCas (in-image, the existing driver pattern), write, re-parse. The re-parse is where the dico's choices are enforced; cas_validate's round trip stays as that gate. Three measured caveats are handled inside the serializer, nowhere else: file keywords are assigned through cas.values[...] (telapy's set() demands the file exist); logicals are handed to telapy as a value whose repr is YES/NO (Python's repr(True) is a word DAMOCLES does not answer to); and string values are handed to telapy as a str subclass whose __repr__ is the engine's own form - a single-quote delimiter with '' inside - because telapy's write() formats with repr() and Python's repr switches to a double-quote delimiter the engine cannot read (Stage 0 measured all four spellings against the box; only 'Nate''s reach' runs). telapy still writes the file; only the delimiter is ours. The engine reads the written file; there is no second serialization path.

def serialize(module, sheet, rundir):
    cas = TelemacCas(path, get_dico(module.name), access="w")
    for keyword, value in sheet.resolved():        # engine defaults are NOT written; the dico supplies them
        cas.values[keyword] = escape(value)
    cas.write(path)
    validate_authored_steering(rundir, {path.name: module.name})
