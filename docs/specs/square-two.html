1. The principle

Every domain job is run by the library that owns that domain; we write the thin, honest glue between them - staging, provenance, refusals, the plan. New code must answer "which library call replaces this?" before it exists.

What we OWN outright (the product, not replaceable by a library): the plan substrate (static plans, doors, journal, rerun), the tool registry and !run, sessions + the gate, MeshArtifact + recipe-as-record, staging economics + the containment rule, typed refusals + provenance. Orchestration and honesty - that is the product.

3. The shape (what everything reuses)

flowchart LR
    F["fetch tools (frozen)"] --> C["chain tools: delineate, corridor_of, ... (LEGO - plan-level, composable)"]
    C --> M["build_mesh: bbox OR polygon domain -> om2d/reg_grid -> session/gate -> MeshArtifact + recipe"]
    M --> D["deck writer (TelemacCas + dico)"]
    D --> B["THE BOX: one generic telapy runner, --network none"]
    B --> R["reader (TelemacFile) -> neutral products"]
    R --> E["emission seam (frozen) -> QGIS"]

The LEGO law governs the chain: domain narrowing is plan-level tool chaining; meshers never grow domain preps; a capability gap is answered by a composable tool, never by growing a stage.

4. The worker unification (next wave)

The worker stops knowing processes. The deck/manifest declares the telapy module, the staged inputs, and the result files; the entrypoint is read manifest -> stage -> telapy runs the case -> collect -> out. NATE pre-deleted the five per-process build scripts; residual build logic moves server-side into deck authoring (the sole-authored-record law) or dies. Ends with an image rebuild + one coarse smoke per process family THROUGH the image. Box contract unchanged; --network none unchanged.

5. The build-back ladder

  1. Chained tools + polygon-domain meshing (IN FLIGHT).
  2. Worker unification (spec section 4) + attic of all non-telemac workers.
  3. om2d wrapper depth vs the four-fragility acceptance bar (deterministic contours, multi-section boundaries, rim sizing honored, lake-capable domains).
  4. TELEMAC templates rebuilt one at a time as native expressions of the principles - steps wrappers dissolve into plan-level dataflow as each template is rebuilt.
  5. Other engines return from the attic through this shape, one at a time.
